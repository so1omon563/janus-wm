# Beliefs

This is a living document. Beliefs explain why Janus's principles exist.

## People Think In Work, Not Windows

A window is rarely the thing a person is trying to manage. It is a visible part
of a larger activity: writing, debugging, planning, researching, reviewing, or
communicating.

## Interruptions Are Inevitable

Janus should assume that focus will be broken. Meetings, messages, app
switching, notifications, and small errands are part of real work.

## The Cost Of Interruption Is Reconstructing Mental State

The expensive part is not only moving windows back. It is remembering what each
window meant, which task it belonged to, and what should happen next.

## Context Is A More Useful Primitive Than Layout

A layout describes where things are. A context describes what work is happening.
Janus should understand layouts as expressions of context, not the other way
around.

## Layouts Are Implementations Of Context

A good layout makes context visible and recoverable. A bad layout can be
spatially efficient while still making the user's work harder to resume.

## Cognitive Continuity Is More Valuable Than Spatial Efficiency

Perfect packing is less important than helping the user preserve their train of
thought. Stable, understandable placement usually beats clever rearrangement.

## Visibility And Discoverability Are Different

Not every capability should be visible all the time. Every capability should be
findable when it becomes relevant.

## Good Defaults Emerge From Lived Experience

Defaults should not be invented abstractly. They should come from observed work,
real friction, and repeated use.

## Evidence Should Refine Beliefs Over Time

These beliefs are not permanent doctrine. They should change when lived product
experience shows that Janus understands the work incorrectly.
