# RFC-0000: Discovering Janus

## Purpose

Capture the discoveries that established the design foundation of the Janus
project.

## Initial Question

What problem is Janus actually solving?

## Discovery

Janus is not fundamentally a window manager.

It is software that reduces the cognitive cost of changing, recovering, and
maintaining context while working.

Window management is an implementation strategy. It is not the product.

## Key Discoveries

- Context precedes layout.
- Layouts are implementations of context.
- The true friction comes from reconstructing mental state after interruptions.
- Cognitive continuity is more important than spatial efficiency.
- Visibility and discoverability are distinct concepts.
- Defaults should be opinionated but never restrictive.
- Capability should exceed visibility.
- Every capability should remain discoverable.
- Janus is discovered, not invented.
- Design artifacts deserve the same stewardship as source code.

## Development Process

Major features should generally follow this lifecycle:

1. Observation
2. Conversation
3. Discovery
4. RFC
5. Figma exploration
6. Prototype
7. Review
8. Implementation
9. Experience
10. New observation

Implementation should generally occur after the design reasoning has been
captured.

The goal is not simply to preserve code. The goal is to preserve understanding.
